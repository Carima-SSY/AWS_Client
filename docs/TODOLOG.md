## 1. 중복 실행 방지

### 목표

같은 장비용 AWSClientApp이 이미 실행 중이면, 새로 실행한 프로세스는 메시지를 출력하고 바로 종료한다.

### 진행 상황

- **2026-10-29 현장 확인:** 4·6호기 통신 불안정의 원인이 AWS Client App 중복 실행으로 확인되었다. 장비 제어 프로그램이 비정상 종료된 뒤 다시 실행되면서 AWS Client App이 하나 더 생성된 경우다.
- **우선 대응:** 장비 제어 프로그램 쪽에서 재실행 시 AWS Client App을 중복 실행하지 않도록 조치했다(다른 담당자, 업데이트 예정).
- **이 작업:** 앱 자체의 중복 실행 방지는 당분간 진행하지 않고 보류한다(사용자 결정). 장비 제어 프로그램 조치 후에도 같은 문제가 생기거나, 사람이 직접 앱을 두 번 실행할 수 있는 환경이 생기면 다시 검토한다.

### 필요한 이유

- 같은 `client_id`로 두 프로세스가 AWS IoT에 동시에 접속하면, AWS가 서로를 끊어 연결과 끊김이 반복된다.
- 두 프로세스가 같은 상태·로그·이력 JSON 파일을 함께 읽고 쓴다. `json_file`의 Lock은 한 프로세스 안의 스레드끼리만 순서를 맞추므로, 다른 프로세스와의 충돌은 막지 못한다.

### 방식: 파일 잠금(OS 잠금)

- 시작하자마자 잠금 파일에 배타 잠금을 건다.
  - Linux/Raspberry Pi: `fcntl.flock(fd, LOCK_EX | LOCK_NB)`
  - Windows: `msvcrt.locking(fd, LK_NBLCK, 1)`
- 잠금을 얻지 못하면 "이미 실행 중"을 출력하고 종료한다.
- 잠금은 프로세스가 끝나면 OS가 자동으로 푼다. 비정상 종료, `kill -9`, 전원 차단 뒤에도 잠금이 남지 않는다.
- 표준 라이브러리만 쓰므로 새 의존성은 없다.

### 다른 방식을 쓰지 않는 이유

| 방식 | 문제 |
|---|---|
| PID 파일 | 비정상 종료 시 파일이 남는다. 그 PID를 다른 프로세스가 다시 쓰면 실행 중으로 잘못 판단한다. |
| 프로세스 이름 검색(psutil) | 새 의존성이 필요하다. PyInstaller `--onefile` 빌드는 실행 하나에 프로세스가 2개(부트로더 부모 + 실제 앱) 떠서 자기 자신을 중복으로 오판한다. |
| localhost 포트 점유 | 다른 프로그램과 포트가 겹칠 수 있다. |
| Windows 이름 있는 뮤텍스 | Windows에서만 동작한다. |

### 구현 시 주의

- **검사 위치:** `if __name__ == "__main__":` 맨 처음, `try` 블록보다 앞에 둔다.
  - `finally`는 종료할 때 `client_status.delete_json_file()`로 상태 JSON 파일을 지운다.
  - 검사가 `try` 안에 있으면, 중복으로 실행된 두 번째 프로세스가 종료하면서 실행 중인 첫 번째 프로세스의 파일을 지울 수 있다.
- **잠금 파일 경로:** `client-config.json`이 있는 폴더처럼 실행할 때마다 같은 경로를 쓴다.
  - PyInstaller onefile의 임시 압축 해제 폴더(`sys._MEIPASS`)는 실행마다 바뀌므로 쓰지 않는다.
- **잠금 단위:** 잠금 파일 이름에 `client_id`(또는 장비 타입·번호)를 넣는다.
  - 예: `AWSClientApp-{client_id}.lock`
  - 한 PC에서 장비 여러 대를 따로 돌려도 `client_id`가 다르면 각각 실행된다.
- **잠금 유지:** 잠금을 건 파일 객체를 프로세스가 끝날 때까지 닫지 않는다(전역 변수로 보관). 닫히면 잠금이 풀린다.
- **자동 재시작 서비스:** systemd 등에 항상 재시작(`Restart=always`)으로 등록돼 있다면, 종료한 중복 프로세스가 반복해서 다시 뜰 수 있다. 서비스 설정을 함께 확인한다.

### 확인 방법

1. 같은 설정으로 두 번 실행하면 두 번째는 메시지를 출력하고 종료하는지 확인한다. 첫 번째의 상태 JSON 파일이 그대로 남아 있는지도 본다.
2. 첫 번째를 강제 종료(`kill -9`, 작업 관리자 종료)한 뒤 다시 실행하면 정상 시작되는지 확인한다.
3. `client_id`가 다른 설정 두 개는 동시에 실행되는지 확인한다.
4. PyInstaller로 빌드한 실행 파일에서도 1~3을 확인한다(Linux, Windows 각각).

## 2. 시작 실패 시 `finally`의 `AttributeError`

### 문제

`if __name__ == "__main__":`은 `aws_client = None`으로 시작한다. `AWSClient(...)` 생성 중 예외가 나면 `aws_client`는 `None`으로 남는다. 이때 `finally`의 `aws_client.iot_core.disconnect()`에서 `AttributeError`가 나서, 원래 예외(설정 오류, 인증서 경로 오류 등)가 가려진다.

### 수정 방향

- `finally`에서 `aws_client`가 `None`이 아닐 때만 `disconnect()`와 `delete_json_file()`을 부른다.
- 1번과 같은 블록을 고치므로 함께 처리한다.
